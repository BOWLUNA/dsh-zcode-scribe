# 测试

```bash
node test/run.mjs
```

**101 项测试 / 15 个套件**，不需要安装、也不需要 harness。
运行器会自己发现本目录下所有 `*.test.mjs`、解析成绝对路径，再交给 `node --test`。
之所以不直接让 Node 去发现目录，是因为在 Windows 上裸 `test` 参数会被当作
**无扩展名的模块路径**解析，于是在任何断言执行之前就以 `MODULE_NOT_FOUND` 挂掉。

## 套件构成

| 文件 | 套件数 | 内容 |
| --- | --- | --- |
| `paths.test.mjs` | 7 | 记忆房间的路径规则：路径穿越、被禁段、Unicode 夹带、NTFS 备用数据流、尾部点折叠、平台相关的大小写折叠、批次的全有或全无 |
| `apply.test.mjs` | 3 | `apply()` 对真实宿主做了什么：行身份、安全的配置默认值、恰好一个提示词段与一个工具、生命周期 effect，以及关掉 `narrowWriter` 时的响亮告警 |
| `recall.test.mjs` | 5 | 索引截断（含「截断绝不静默」）、frontmatter 读取、根路径解析，以及工具 `execute()` 对**磁盘上真实目录**的行为 |

## 刻意不做 mock 的地方

`recall.test.mjs` 在操作系统临时目录里建**真实目录树**，并按宿主的方式调用工具。
读取路径上有意思的失败都是文件系统层面的——房间不存在、主题逃出房间、文件读不了——
而 mock 出来的文件系统只会测到 mock 本身。

插件是按宿主的方式导入的：**真实的 `index.js`**，不是它的复刻。

## 关于「意图」的断言针对未编译的定义

`recallDefinition()` 返回编写对象；`recallTool()` 返回 `defineTool` 的产物。
凡是关于**意图**的断言——名字、可选参数、输出契约、并发声明——都针对定义做，
因为宿主的包装层在 dsh `0.1.5-rc.2` 与 `0.1.6-alpha.2` 之间**不是稳定契约**。
对编译后的工具，只断言「可调用」。

## 计数

这些总数都是**写在文档里的数字**：`tools/verify-doc-numbers.mjs`
会把仓库里每一处 `N tests` / `N 项测试` 与真实运行比对，漂移就让构建失败。
如果你加了测试，就要预期同时更新本文件。
